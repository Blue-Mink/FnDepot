# v3.0.1
<!-- release-title: 修复通知渠道配置被写坏后无法自愈、定时备份漏任务视图，耗时改用时分秒 -->

## 版本概览

`v3.0.1` 是 `v3.0.0` 的修复版。主要修掉两个会**静默损坏数据**的问题：通知渠道的配置项如果被写成了非字符串（APP 旧版本编辑邮件渠道会触发），该渠道的所有通知包括「测试」按钮都会失败，而界面上没有任何提示；定时备份的默认勾选漏掉了「任务视图」。

同时把通知渠道的字段定义收进服务端，Web 与 APP 从此读同一份，面板加字段两端自动跟上。

## 修复

- **通知渠道配置被写坏后现在能自愈**：服务端会把布尔、数字这类可逆的值归一成字符串，所以受影响的渠道**打开编辑再保存一次就恢复了**，不需要动数据库。真正无法解析的对象/数组会被拒绝并指出是哪个键，而不是存进去之后默默发不出通知。

  > 受影响的是用旧版 APP 编辑过邮件渠道的用户。表现是该渠道所有通知连同「测试」按钮一起失效，而 Web 上只看得到 SSL 那个下拉是空的。

- **定时备份默认包含「任务视图」**：注册表里的默认值漏了这一项，导致**从未保存过备份设置的实例**，定时备份不含分组视图与自定义筛选排序。已修正并加了回归测试锁住「声明的默认值」与「实际生效的默认值」必须一致。

  > 已经保存过备份设置的实例不受影响。升级后如果发现定时备份仍不含任务视图，去设置页把它勾上保存一次即可 —— 没有做自动迁移，因为库里「用户主动取消勾选」和「被这个缺陷写进去的默认值」是同一个值，无法区分。

- **任务耗时改用时分秒**：原来一律显示秒，跑久的任务会出现 `4711.9s` 这种读不出来的数字，现在显示 `1h18m`。分档是 `856ms` / `12.3s` / `5m12s` / `1h18m`。定时任务列表、仪表盘日志等处一并调整。

- **环境变量告警不再每次运行都刷屏**：同一个问题只在第一次触发时报一次，之后静默。变量继续变大不重复提醒（同一个问题在恶化，你已经知道了），但**新增**一条超限变量会重新报（那是新情况）。面板重启后会再提醒一次，让你知道问题还在。

## 优化

- **通知渠道的字段定义收归服务端**：22 个渠道、90 个字段的定义此前在服务端发送逻辑、Web 表单、APP 表单、接口文档四处各存一份，已经出现过不一致。现在服务端持有唯一一份并通过 `/api/notifications/types` 下发，Web 与 APP 都读它。

  加了一个测试把这份定义与实际的发送逻辑**双向绑死**：服务端读了某个配置项但定义里没有，或者定义里有但服务端从来不读，两种情况都会让 CI 失败。所以以后加渠道、加字段只需要改一个地方。

- **系统配置下发渲染信息**：`/api/configs` 现在带上标题、分组中文名、顺序、取值范围与密文标记。APP 端据此把可配置项从 10 项扩到了全部 47 项 —— 备份计划、验证码、资源告警阈值、会话上限、时区等此前在手机上改不了。

- **设置页补上 schema 兜底区**：此前 47 项配置里有 3 项（运行时日志输出、守护方式、systemd 服务名）在 Web 端**完全没有 UI**，现在能看到了。兜底区不是写死的名单，而是「服务端注册的项 − 已有专属表单的项」算出来的 —— **以后服务端新增配置项，Web 什么都不用改就会显示出来**。

  > 守护方式与 systemd 服务名渲染成只读：它们是 `ddp service install` 写入的安装事实，不是偏好。服务名改错会导致面板起不来，而正因为起不来就没法再从面板改回去。
  >
  > 图片上传、取色器、备份内容复选框这类带定制控件的配置项仍然用专属表单——通用渲染器做不出它们，硬换等于重画一遍设置页。

## 配套的 APP 版本

APP `v1.3.0` 与本版配套发布，但**两边互不依赖**：APP 在旧面板上会自动降级，面板升级后不装新 APP 也能正常用。
