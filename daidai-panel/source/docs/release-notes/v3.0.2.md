# v3.0.2
<!-- release-title: 任务半路静默死亡不再记成成功，修复移动端全屏弹窗少 8vw 与 Open API 少一个权限 -->

## 版本概览

`v3.0.2` 的主题是**消灭静默失败**——系统在出问题时不再假装一切正常。

最重要的一条：Node 任务如果跑到一半卡死然后悄悄退出，面板过去会把它记成**成功**（绿勾、不发通知）。这一版能识别出来并判为失败。

## 修复

- **任务半路静默结束不再被记成成功**：Node 脚本里如果有 `Promise` 永远不完成，`await` 它的调用就永久卡住，事件循环随后排空，**node 会以退出码 0 干净退出**——从面板外面看和「跑完了」一模一样。过去这种情况任务显示绿勾、不发失败通知，用户只能靠日志戛然而止看出不对。

  现在面板会检测到并判定为失败，日志里给出 `[任务疑似半路结束]` 提示。

  > 最常见的触发写法是「请求在响应中途断开」：代码只在请求对象上挂了 `error` 监听，而 Node 在响应已经开始之后是把错误发给响应对象的，于是那个 Promise 永远不会 settle。

  这个检测**有无法消除的误报**——「被抛弃的 Promise」和「被卡住的 Promise」在结构上完全一样，只有脚本自己知道工作做没做完。所以准备了三条豁免通道，从精确到粗放：

  | 方式 | 影响范围 |
  |---|---|
  | 脚本末尾加一行 `globalThis.daidaiDone?.()` | 只豁免这个脚本 |
  | 给该任务加环境变量 `DAIDAI_SILENT_EXIT_DETECT=0` | 只豁免这个任务 |
  | 系统设置 → 任务 → 关闭「检测脚本半路静默结束」 | 全部任务 |

  详见 [脚本 API 文档](../script-api.md)。只有 `.js` / `.mjs` / `.ts` 任务有这套检测——Python 和 Shell 没有这个失败模式，它们卡住时进程会一直挂着，最终走任务超时。

- **移动端「全屏」弹窗现在是真的全屏**：`≤768px` 下所有全屏弹窗高度是满的、宽度却少 8vw，左右露出两条遮罩边。全站 **48 个全屏弹窗**都受影响。

  > 根因是 CSS 层叠：移动端给弹窗兜底的 `width: 92vw !important` 带 `!important`，而 Element Plus 实现全屏靠的是不带 `!important` 的 `--el-dialog-width: 100%`，后者根本没机会参与计算。

- **Open API 应用建不出「通知渠道」权限**：服务端强制 8 个权限范围，Web 的勾选列表只列了 7 个，漏掉 `notifications`。表现不是报错，而是**这个权限永远勾不上**，建出来的应用调通知接口一律 403，界面上还看不出少了什么。

  已补齐，并加了测试把服务端实际强制的范围与 Web 的勾选列表双向绑死：以后服务端加了 Web 没加、或 Web 列了服务端不认，两个方向都会让 CI 失败。

  > 同一处漏项在 APP 上更严重（少了 `notifications` 和 `backup` 两个），已在配套的 APP `v1.3.1` 里一并修掉。

- **修正 `v3.0.1` 发布说明里的配套 APP 版本号**：原文写「配套 APP `v1.2.7`」，但 `v1.2.7` 从未发布过——它被提升成了 `v1.3.0`。

## 内部改动

- **Windows 上现在能跑通全量后端测试**：4 个用例此前在 Windows 上必然失败，原因是 Git Bash 会把路径里的反斜杠当转义符吃掉，脚本里的相对重定向落不了盘。这些用例验的是 POSIX shell 行为（`ARG_MAX`、环境变量传递），只在 Linux 上有意义，现在会自动跳过。

  > 对使用者没有任何影响，但它挡着发布前预检——预检要求 `go test ./...` 全绿。

## 配套的 APP 版本

APP `v1.3.1` 与本版配套发布，但**两边互不依赖**：APP 在旧面板上会自动降级，面板升级后不装新 APP 也能正常用。
